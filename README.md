# C+ Агент

Многостраничный сайт с регистрацией пользователей по e-mail и встроенным ИИ-консультантом (чат Timeweb Cloud AI Agent). Дизайн — в стиле сайта [consultant.ru](https://www.consultant.ru): светло-серый фон, фиолетовые и оранжевые акценты.

Публикуется на GitHub Pages: `https://alllexk.github.io/cplusagent/`

## Возможности

- Регистрация и вход по e-mail (Supabase Auth) — формы входа и регистрации находятся на **разных страницах**, поэтому после авторизации они больше не показываются: страницы `login.html` и `register.html` автоматически перенаправляют вошедшего пользователя в консультацию.
- Кнопка **«Выйти»** в шапке справа отображается только авторизованному пользователю (рядом с его именем и e-mail).
- **Восстановление забытого пароля**: письмо со ссылкой → страница установки нового пароля.
- Чат доступен **только после входа**: до авторизации вместо чата показывается заблокированная карточка с кнопками «Войти» и «Зарегистрироваться».
- **Голосовой чат** с ИИ-агентом Timeweb Cloud прямо на странице (не плавающая кнопка): вопрос можно задать голосом через микрофон, ответ агента озвучивается вслух.
- **Текст ответа открывается только после прочтения**: фразы появляются в чате по мере того, как их прочитывает синтезатор речи, — прочитать ответ раньше, чем услышать, нельзя.
- Адаптивная вёрстка в стиле КонсультантПлюс.


## Как устроена авторизация

Все страницы подключают три скрипта: `js/config.js`, `js/auth.js` и `js/app.js` (на [chat.html](chat.html) к ним добавляется `js/voice-chat.js`). `js/auth.js` создаёт единый объект `window.CPlusAuth`:

- лениво загружает `supabase-js` с CDN и создаёт клиент (`persistSession`, `autoRefreshToken`, `detectSessionInUrl`);
- следит за состоянием сессии (`onAuthStateChange`) и рисует правый блок шапки: гостю — «Вход» и «Регистрация», вошедшему — имя, e-mail и кнопку **«Выйти»**;
- содержит методы `signIn`, `signUp`, `signOut`, `sendPasswordReset`, `updatePassword` и перевод ошибок Supabase на русский язык.

Чтобы формы не «мигали» при загрузке, у `<body>` стоит класс `auth-pending`: до определения состояния сессии блок в шапке и карточки с формами скрыты (`visibility: hidden`), а после — снимается через `CPlusAuth.reveal()`.

`js/app.js` — диспетчер страниц: по атрибуту `data-page` у `<body>` запускается нужный модуль (`initHome`, `initLogin`, `initRegister`, `initForgot`, `initReset`, `initChat`). Страницы входа и регистрации перенаправляют уже авторизованного пользователя (`?next=` используется только если это безопасное имя страницы, иначе `chat.html`).

## Восстановление пароля

1. На странице [login.html](login.html) — ссылка «Забыли пароль?» → [forgot-password.html](forgot-password.html).
2. Пользователь вводит e-mail, Supabase отправляет письмо со ссылкой, ведущей на [reset-password.html](reset-password.html) (`redirectTo` формируется автоматически от текущего адреса сайта).
3. Ссылка содержит токены восстановления. `supabase-js` сам создаёт по ним сессию, после чего на странице появляется форма нового пароля (пароль + подтверждение, минимум 6 символов).
4. Если ссылка устарела или уже использована — показывается понятное сообщение и ссылка на повторный запрос.
5. Если Supabase по какой-то причине приводит пользователя на другую страницу (например, на Site URL), модуль `js/auth.js` перенаправляет его на `reset-password.html`, сохраняя токены из адреса.

> **Важно для работы восстановления и подтверждения e-mail.** В Supabase → **Authentication → URL Configuration** должны быть указаны:
>
> - **Site URL**: `https://<username>.github.io/cplusagent/`
> - **Redirect URLs**: `https://<username>.github.io/cplusagent/**`
>
> Для локальной отладки добавьте в **Redirect URLs** также `http://localhost:8000/**` (или ваш порт).

## О чате

Чат — собственный (не виджет), встроен в страницу [chat.html](chat.html) и реализован в [js/voice-chat.js](js/voice-chat.js). Запросы уходят напрямую из браузера в OpenAI-совместимый API агента Timeweb Cloud:

```
POST https://agent.timeweb.cloud/api/v1/cloud-ai/agents/895689ca-80d3-46ec-b694-36c75a60b00f/v1/chat/completions
Authorization: Bearer <API-токен агента>
{ "messages": [ ... ], "stream": true }
```

Ответ приходит потоком (SSE: `data: {...}` с `choices[0].delta.content`), поэтому озвучка начинается, не дожидаясь конца ответа.

### Как работает голосовой режим

1. **Вопрос голосом.** Кнопка «🎤 Голосом» включает распознавание речи (`SpeechRecognition`, язык `ru-RU`). Распознанный текст печатается в поле ввода, а после финального результата автоматически отправляется агенту. Текстовый ввод остаётся как запасной вариант.
2. **Озвучка ответа.** Поток разбивается на фразы по границам предложений, каждая фраза проговаривается через `speechSynthesis` (голос `ru-RU`, предпочтение отдаётся «естественным» голосам, если они установлены в системе).
3. **Раскрытие текста только после прочтения.** Пузырь ответа появляется сразу, но вместо текста в нём плашка «🔊 Читаю вслух — текст появляется после прочтения». Очередное предложение дописывается в пузырь ровно в тот момент, когда его озвучка завершилась (`onend`), поэтому прочитать ответ раньше, чем услышать, невозможно.
4. **Остановка.** Кнопка «Остановить и показать текст» прерывает запрос и озвучку и сразу раскрывает весь текст, включая непрочитанные фразы. Отправка и микрофон на время ответа блокируются.

Если в браузере нет голосов синтеза речи, озвучка считается недоступной: об этом выводится предупреждение, а текст раскрывается (иначе ответ остался бы навсегда скрытым).

### Требования к браузере

| Возможность | Требование |
| --- | --- |
| Распознавание речи | Chromium-браузеры: Chrome, Edge, Яндекс Браузер. В браузерах без поддержки кнопка микрофона скрывается, остаётся текстовый ввод |
| Синтез речи | `speechSynthesis` — поддерживается во всех современных браузерах; для русского голоса нужен хотя бы один установленный ru-голос в системе |
| Микрофон | Только `https://` или `localhost`, иначе браузер не даст доступ к микрофону |

### API-токен агента

Токен доступа агента берётся в панели Timeweb Cloud: **Агенты → Управление → Доступ по API** (показывается один раз).

- Вводится в самом чате (кнопка **«API-токен»**) и сохраняется в `localStorage` браузера под ключом `cplusagent_agent_token`; кнопка **«Удалить»** стирает его.
- Альтернатива для локальной разработки: создать файл `js/config.local.js` (он в `.gitignore`) и подключить его перед `js/voice-chat.js`:

```js
window.AGENT_CONFIG = { token: "ваш-API-токен" };
```

При первом открытии чата такой токен копируется в `localStorage`, поэтому кнопка «Удалить» продолжает работать.

### Состояние диалога

История сообщений хранится в `sessionStorage` (`cplusagent_voice_dialog`), агенту отправляются последние 20 сообщений. Восстановленные после перезагрузки ответы показываются целиком — они уже были прочитаны вслух ранее. Кнопка **«Новый диалог»** очищает ленту и историю; при выходе из аккаунта диалог также сбрасывается.

**Доступ к чату ограничен:** чат монтируется только после успешного входа (сессия Supabase или демо-вход). Пока пользователь не авторизован, в карточке показывается блок с приглашением войти; после выхода чат размонтируется (`unmount()`) вместе с запросом и озвучкой, и доступ снова закрывается.

**Демо-вход:** пока Supabase не настроен, на странице входа появляется блок «Войти в демо» — он имитирует вход, открывает чат и сохраняет сессию на время вкладки (sessionStorage). Это позволяет проверить весь сценарий до настройки бэкенда.

## Настройка Supabase (регистрация по e-mail)

1. Создайте проект на [supabase.com](https://supabase.com) (бесплатный план подойдёт).
2. В панели проекта откройте **Settings → API**.
3. Скопируйте значения **Project URL** и **anon public** в файл [js/config.js](js/config.js):

```js
window.SUPABASE_CONFIG = {
  url: "https://ваш-проект.supabase.co",
  anonKey: "******"
};
```

4. В **Authentication → Providers** убедитесь, что включён провайдер **Email**.
5. В **Authentication → URL Configuration** пропишите Site URL и Redirect URLs (см. раздел «Восстановление пароля»).
6. При необходимости отключите **Confirm email**, если не хотите подтверждать адрес перед входом (по умолчанию подтверждение включено).

> **Важно.** Поля можно заполнить и после публикации — приложение будет работать в «демо-режиме» (чат доступен через демо-вход, регистрация по e-mail показывает подсказку о настройке).

## Локальный запуск

```bash
# из папки проекта
python3 -m http.server 8000
# открыть http://localhost:8000/index.html
```

После правок в `css/style.css` или `js/*` увеличивайте номер версии в ссылках (`?v=N`) на всех страницах — иначе браузер и CDN GitHub Pages могут отдать старые файлы из кеша.

## Публикация на GitHub Pages

```bash
git add .
git commit -m "C+ Агент: многостраничный сайт"
git push
```

1. В репозитории откройте **Settings → Pages**.
2. В разделе **Build and deployment → Source** выберите **Deploy from a branch** и укажите ветку `main`, папку `/ (root)`.
3. Сохраните — сайт будет доступен по адресу `https://<username>.github.io/cplusagent/`.

> Проект не использует систему сборки: для GitHub Pages достаточно выложить файлы из корня репозитория.

## Безопасность

- `anon`-ключ Supabase — публичный ключ, предназначенный для использования в браузере. Однако убедитесь, что в **Supabase → Authentication → Policies** доступ к таблицам данных ограничен (по умолчанию для новых проектов доступ закрыт).
- Не храните в [js/config.js](js/config.js) секретные ключи — только `anon public`.
- **API-токен агента** — секрет: он даёт право обращаться к агенту от вашего имени. Чат хранит его только в `localStorage` того браузера, где он введён, и передаёт исключительно в `agent.timeweb.cloud`. Локальный файл `js/config.local.js` добавлен в `.gitignore` — не коммитьте его и не вставляйте токен в HTML/JS репозитория.
